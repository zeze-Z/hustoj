# 教师推广积分奖励 — 需求文档

> 版本: v1.2  日期: 2026-09-02  状态: 实施完成，待验收
>
> v1.2 变更：结算改为管理端手动触发（删除定时任务）；教师端不单独做推广卡片，推广积分直接在 point_index.php 积分流水中展示；新增 admin「教师推广统计」子菜单页，管理员查看各教师数据并手动点「奖励推广」发分+邮件通知。
> v1.1 变更：绑定入口改为直接在 user_import.php 导入页加"归属教师"下拉（仿目标学校选框），不新增独立绑定页；"本周登录过"判定字段确认为 users.accesstime（已验证 login.php:143 登录后更新）；删除邀请码相关描述。

## 一、背景与目标

通过已入驻教师推广 OJ 平台：教师找客服导入班级学生，建立师生关联；
教师持续运营（让学生每周登录），连续 4 周达标可获积分奖励。
形成「教师拉学生 → 学生留得住 → 教师持续受益」的增长飞轮。

## 二、核心规则

### 2.1 不变项（保持现有逻辑）
- 学生注册/激活积分逻辑不变（现有 `login_reward.php`：注册6分 + 连续7天每天2分）
- 教师注册/激活积分逻辑不变
- 教师导入学生 **不发积分**（导入只建立师生关联）
- 学生 **不发推广积分**

### 2.2 教师周奖励（核心）

| 项 | 规则 |
|---|---|
| 触发条件 | 教师关联学生中，**本周登录过** 的人数 ≥ 关联学生数 × 60%（向下取整） |
| 奖励 | 每周达标发 **5 积分** |
| 周期 | 连续 **4 周**，每周达标每周发 |
| 断周 | 某周未达标 → **停止后续发放**（已发不回收），类似现有签到断签 |
| 上限 | 单教师最多 4 × 5 = 20 积分 |

**举例**：教师关联 10 个学生，60% = 6 人。
- 第1周 6 人登录 → 发 5 分
- 第2周 6 人登录 → 发 5 分
- 第3周 5 人登录 → 不发且结束，第4周不再发
- 最多 4 周 × 5 = 20 分

## 三、边界与默认决策

以下为规划阶段默认决策，实施前可调整：

| 边界点 | 默认决策 | 说明 |
|---|---|---|
| "本周"时间窗 | 自然周（周一00:00~周日23:59） | 与签到引擎按天风格一致 |
| 60% 取整 | floor 向下取整 | 10人→6人，7人→4人 |
| 0 关联学生 | 不参与奖励 | 无意义 |
| 4周周期起点 | 教师首次有关联学生的那周起算 | 符合"导入学生才能享激励"因果 |
| 结算时机 | 管理员在「教师推广统计」页手动点击「奖励推广」按钮触发 | 不做定时任务，管理员主动掌控 |
| 关联学生上限 | 200 人 | 防导入大量僵尸号拉低60%门槛 |
| 关联唯一性 | 一个学生只归属一个教师 | 换教师不重发 |

## 四、关联关系建立

学生账号由教师找客服导入，导入时直接选择归属教师，无需新增独立绑定页：
- `users.bind_teacher_id` 记录归属教师
- **绑定入口**：直接在管理端 `admin/user_import.php`（用户-导入页）加"归属教师"下拉选择框，操作方式与现有"目标学校"选框一致（见 user_import.php 第262-272行目标学校 select 写法）
- 导入时把所选教师 user_id 写入每个新学生的 `bind_teacher_id`
- 一个学生只归属一个教师，重复导入以最后一次为准（导入本就不发分，无重发问题）

## 五、新增积分日志类型

现有 type：1充值卡 / 2课件 / 3管理员 / 4系统
**新增 type=5 推广奖励**，与系统奖励区分，便于推广效果统计与风控审计。
同步加 `POINT_LOG_TYPE_PROMO` 常量，更新 `point_index.php` 筛选项。

## 六、数据模型变更（需 SQL 归档到 db/）

SQL 变更必要性评估（已评估，均为最小必要，无法复用现有表替代）：

1. `users` 新增字段 `bind_teacher_id` VARCHAR(48) NULL —— 学生归属教师
   - 必要性：现有无此关系字段（school_id 是学校非教师，group_name 是自由文本不可靠），必须 ADD COLUMN
2. 新增表 `teacher_promo_stat` —— 教师推广周结算状态记录
   - 字段：教师ID、week_start(周一日期)、当前周次(1-4)、关联学生数、本周活跃学生数、达标阈值、是否达标、是否已发放、发放积分、结算时间、status(0进行中/1完成/2中断)
   - 必要性：断周判定、按钮置灰（未达标/已完成/已中断）、当前周次/4 展示都需要"即使未发分也有结算记录"。point_log 只在发分成功时写流水，查不出"未达标的那周"，无法替代
   - uk_teacher_week 唯一键防同一周重复结算
3. ~~teacher_promo_log（明细事件账）~~ —— **不建**。point_log(type=5) 记发分流水 + teacher_promo_stat 记每周状态，审计链路已完整，无需额外表

## 七、前端入口

- **教师端**：不单独做推广数据卡片（关联学生数/活跃数等数据不给教师看）。教师获得的推广积分直接在 `point_index.php` 积分流水中展示（通过 type=5 筛选可见）。
- **推广奖励说明（教师可见）**：在 `point_index.php` 积分中心页 和 `course_my.php` 课程页 两处都加「推广奖励说明」卡片，仅教师身份（`$_SESSION[$OJ_NAME.'_teacher']`）显示。说明内容含：
  - 奖励规则：导入学生后，每周若有 60% 关联学生登录，教师可得 5 积分
  - 周期：连续 4 周，每周达标每周发，断周即结束，最多 20 积分
  - 参与方式：联系客服导入班级学生即可参与
  - 积分用途：积分可用于兑换/购买课件等
- **管理端**：在积分管理菜单下新增子菜单页「教师推广统计」（`admin/teacher_promo_list.php`），仅管理员可访问：
  - 列表展示每位教师的：关联学生数、本周活跃数、当前周次/4、累计推广积分
  - **页面顶部「统计上周数据」按钮**：点击后遍历所有有关联学生的教师，对上周生成结算快照写入 teacher_promo_stat（INSERT IGNORE，uk_teacher_week 防重；含 bound_count/active_count/threshold/is_qualified 判定，is_granted=0 未发）。打开页面默认只读展示已有 stat 记录，不自动统计，避免数据库负载
  - 每个教师记录行尾的「奖励推广」按钮按状态控制：
    - **达标且未发**（is_qualified=1, is_granted=0）→ 可点击，点击后：
      1. 发放 5 积分（type=5），UPDATE 该条 is_granted=1，推进周次，写 status
      2. 推送邮件通知教师（复用现有 PHPMailer）
    - **未达标**（is_qualified=0）→ 置灰不可点击（展示活跃数/阈值，让管理员知道差多少）
    - **已发放 / 已完成4周 / 已中断** → 置灰不可点击
  - 周次/断周逻辑同前：满4周完成、断周中断已发不回收
