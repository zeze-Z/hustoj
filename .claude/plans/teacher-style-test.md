# 《测一测，你是哪位教育家》趣味测评 H5 实施计划

## 目标

在 HUSTOJ 站内新增一个面向教师的趣味测评 H5（8 题单选 → 匹配一位教育家伟人 → 结果页 + 分享卡片），从 `more.php#teacher` 卡片入口进入，用好奇心钩子吸引老师使用平台（课程表 / 课件 / 课前小游戏导流）。需求已经用户确认，本计划为编码输入。

## 背景 / 根因

教师服务 Tab 目前只有工具型入口（账号批量开通、课程表），缺"钩子型"内容让用户愿意点、愿意转。参考城市匹配测试 H5 的"轻测评 + 伟人对标 + 分享卡片"模式补齐。

## 已确认的需求决策（不得偏离）

- 主题：教育家圣殿——结果对标孔子 / 苏格拉底 / 陶行知 / 韩愈 / 蔡元培 / 蒙台梭利（6 维度一一对应）
- 纯前端浏览器本地计算；**无需登录**；MVP 不落库、不采集个人信息、无埋点后端、无 DDL
- 落地页静态数字"已有 7821 位老师测过"
- 转化区 3 个导流入口：课程表生成器（timetable.php）/ 课件（course.php）/ 课前小游戏（more.php#games），另加"登录解锁更多"轻提示（链接 loginpage.php）
- 匹配度归一化到 70%~97%；结果页底部"仅供娱乐参考"
- UI：**frontend-design skill**（`.claude/skills/frontend-design/SKILL.md`，编码前先读）+ 用户指定**可爱有趣**视觉风格；**移动端优先**（375~428px 主战场），其次 web 端

### 题库（8 题 × 4 选项，隐藏权重）

题目场景（文案可微调但场景不变）：①新学期第一节课开场 ②学生代码报错 ③学生课上偷偷玩游戏 ④学生问超纲问题 ⑤评价学生作品最看重什么 ⑥课后作业风格 ⑦学生用 AI 生成代码 ⑧期末展示课想看到什么。

设计约束（与城市测试 PRD 同）：每维度至少被 2 个选项触达；同一维度权重方向全局一致；题库数据与页面代码分离。

### 匹配算法

答案 → 6 维偏好向量 → 与 6 教育家画像向量算相似度 → min-max 归一化映射 **70%~97%**。Top1 = 主结果；Top2 = "你的隐藏第二人格"（小卡片 + 匹配度，引诱重测）。

### 结果页结构（顺序固定）

1. 匹配度百分比环形动效
2. "你的教学灵魂是——XX"（教育家名 + 一句话定位，配可爱头像/插画）
3. 3 标签 + 3 关键词胶囊
4. 名言金句区（仪式感核心，引用样式）
5. 个性化理由 80~150 字（按用户得分最高 2~3 维度从教育家画像 description 拼接；每维度段落 2 变体轮换）
6. 六维能力雷达（Canvas 或 SVG）
7. 第二人格小卡片
8. 转化区：3 张导流卡片（课程表生成器 / 课件 / 课前小游戏）+ "登录解锁更多"轻提示
9. 操作区：生成分享卡片 / 重新测试
10. 底部"仅供娱乐参考"

### 分享卡片

前端 Canvas 生成 **750×1334** 竖版图：教育家称号 + 匹配度 + 3 标签 + 名言 + 平台名（$OJ_NAME）+ 钩子文案"我的教学灵魂是孔子，测测你是哪位教育家？" + 二维码（指向测试页 URL，`template/syzoj/js/qrcode.min.js` 本地 vendor，参考 timetable.js:364 用法）。支持长按/右键保存；微信内给"长按保存图片"引导语。生成后展示在页面内（canvas 或 toDataURL 图片）。

## UI 规格（可爱有趣 + frontend-design skill）

编码前先通读 `.claude/skills/frontend-design/SKILL.md` 并按其"两遍工作法"先产出设计 token 再写码。方向约束：

- **气质**：绘本/贴纸感的可爱有趣——圆润造型、贴纸徽章、波浪/点线分隔、手绘感小装饰；不是 SaaS 卡片模板风。每个教育家有自己的主题色（做成贴纸徽章）。
- **色板**（可在此基础上微调，禁止无理由换向）：纸感米白底 `#FFF8F0`、墨青主色 `#2B4C6F`、珊瑚橙 `#FF7B54`、蜜黄 `#FFC93C`、薄荷绿 `#6BCB9A`、藕粉 `#FF9FB2`；六教育家各配一枚专属色。
- **字体**：中文圆润字重（`"PingFang SC","Microsoft YaHei"` + 重字重 700/800），标题可以做大、做俏皮（贴纸旋转、描边字），避免 skill 列出的 AI 默认套路（奶油底+衬线+陶土橙、全大写 eyebrow、每节淡入上滑等）。
- **动效**：克制——单次编排（结果页揭晓一刻的环形动效 + 一次礼花，可复用 `template/$OJ_TEMPLATE/game_confetti.js` 的做法，CDN 失败则静默降级）；答题页点选进题的过渡要轻快。
- **移动端优先**：375px 起设计，触控目标 ≥44px，一屏一题；web 端居中限宽（参考 more-page max-width 惯例）不做花活。
- **质量底线**：可见键盘焦点、`prefers-reduced-motion` 降级、对比度可读、CSS 类名统一前缀（如 `ts-`）防选择器冲突。

## 验证步骤

1. `php -l` 自测所有改动 PHP 文件
2. 部署 web-2204（deploy-test-env skill，模板/页面改动须 `-f` 清 APCu）
3. tester（browser-use，移动端视口 375px 优先）：
   - more.php#teacher 入口卡片可见、点击进入测试页
   - 落地页显示 7821 静态数字 → 答完 8 题 → 出结果（匹配度 70~97、名言、理由、雷达、第二人格）
   - 生成分享卡片（图片出现、含二维码与文案）
   - 转化区 3 个链接分别可达（timetable.php / course.php / more.php#games）
   - 重新测试回第一题
   - 游客（未登录）全流程可玩；页面级 GET 带浏览器 UA
4. reviewer 验收（git diff + ?? 新文件清单 + 本 plan）

## 验收标准

- 全部验证步骤通过；无 BLOCKING 问题
- 模板只改 syzoj；游客白名单生效；无 SQL/CSRF/XSS 问题（动态输出统一 htmlentities，本页无用户输入入库）
- 匹配度永远落在 70%~97%；8 题各维度覆盖均匀无恒零维度
- 移动端 375px 布局不破版；可爱有趣风格符合上述 UI 规格
