# 教师推广积分奖励 — 实施方案

> 版本: v1.0  日期: 2026-09-02  状态: 待批准
> 需求文档: `.claude/plans/教师推广积分奖励_需求.md`

## 一、目标与规则回顾

教师找客服导入学生建立关联 → 每周若 60% 关联学生登录过则教师得 5 分
→ 连续 4 周每周达标每周发 → 断周即结束。最多 20 分。

- 学生/教师注册积分逻辑不变
- 导入学生、学生本人都不发推广积分
- 60% = 本周登录过的关联学生数 ÷ 关联学生数，floor 取整
- 自然周（周一00:00~周日23:59）
- 4周从教师首次有关联学生的那周起算
- 定时任务每周一结算上周
- 关联上限 200 人，一个学生只绑一个教师

### 2.3 核心函数库 `trunk/web/include/teacher_promo.php`（新增）

```php
// 常量
TEACHER_PROMO_WEEKS = 4          // 连续4周
TEACHER_PROMO_WEEKLY_POINT = 5   // 每周5分
TEACHER_PROMO_RATIO = 0.6        // 60%阈值
TEACHER_PROMO_MAX_BIND = 200     // 关联学生上限

// 核心函数
get_teacher_bound_students($teacher_id)       // 取关联学生列表
get_teacher_active_count($teacher_id, $week_start, $week_end)  // 本周登录过的学生数（用 accesstime）
teacher_promo_settle_week($teacher_id, $week_start)  // 结算单教师单周：判定→发分→写stat→断周
teacher_promo_settle_all($week_start)                 // 定时任务：遍历所有进行中教师结算上周
get_teacher_promo_progress($teacher_id)               // 教师端展示用：当前周次/4、关联数、本周活跃、累计
```

**结算逻辑伪代码**（teacher_promo_settle_week）：
```
1. 查 teacher_promo_stat 该教师最新状态
   - 无记录 → 若该教师当前关联学生数>0，则 week_no=1 起算；否则跳过
   - 有记录 status=0(进行中) → week_no = 上周+1；若 week_no>4 跳过
   - status=1/2 → 跳过
2. bound_count = 关联学生数（上限200）
3. threshold = floor(bound_count * 0.6)
4. active_count = 关联学生中 accesstime 在 [week_start, week_end] 的数量
5. is_qualified = active_count >= threshold ? 1 : 0
6. 若达标：
   - point_apply_change(teacher_id, 5, POINT_LOG_TYPE_PROMO, week_start, '推广周奖励 第N周')
   - is_granted=1, grant_point=5
   - week_no==4 → status=1(已完成) 否则 status=0(进行中)
7. 若未达标：
   - is_granted=0, grant_point=0
   - status=2(已中断)，不再继续后续周
8. INSERT/UPDATE teacher_promo_stat
```

## 三、验收标准

1. `php -l` 全部新增/改动文件无语法错误
2. SQL 归档文件格式符合规范（末尾有回滚语句）
3. 导入页"归属教师"下拉能列出 teacher 权限用户，导入后 users.bind_teacher_id 正确写入
4. 一个学生重复绑定不同教师，以最后一次为准（不重发奖励，因导入本就不发分）
5. 手动模拟结算：教师关联10学生，6人 accesstime 在本周 → 结算后教师 +5 分，stat 记录正确
6. 未达标（5人登录）→ 不发分且 status=2，下周不再结算
7. 满4周达标 → status=1，第5周不再发
8. point_log 有 type=5 记录，remark 标注周次
9. 积分中心能按"推广奖励"筛选流水
10. 权限：teacher_promo_settle.php 仅 administrator 可执行（防被外部调用刷分）
11. 参数化查询，无注入；XSS 用 htmlentities

## 五、风险与注意

- **accesstime 更新时机**：已验证 `login.php:143` 登录成功后 `UPDATE users SET accesstime=now()`，用 accesstime 判定"上周内是否登录过"正确充分（结算取上周时间窗，accesstime 落在上周即算活跃）
- **定时任务未被调用**：纯靠 cron，需确保虚机/生产机有配置；MVP 也可提供管理端手动触发入口
- **0 关联学生不参与**：避免无意义结算
- **学校模式联动**：导入页学校模式下既有目标学校选框又加教师选框，两者并存不冲突（教师选框始终显示，非学校模式也可用）
