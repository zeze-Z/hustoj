# 20积分分批发放需求文档（修订版）

**版本：** v1.1
**日期：** 2026-07-24
**状态：** 评审修订完成，待开发

---

## 一、背景

当前新用户注册一次性发放20积分，薅羊毛成本低。改为分批发放，提升用户留存和活跃度。

---

## 二、活动规则

| 规则 | 说明 |
|------|------|
| 参与对象 | 仅新注册用户，存量账户不参与 |
| 注册奖励 | 注册/激活即发 **6积分** |
| 连续登录奖励 | 连续登录7天每天 **2积分**（共14积分），第7天签到后标记完成 |
| 断签处理 | 中断后不再发放（`login_reward_status=2`，直接结束，非重置） |
| 注册当天 | 登录不额外发放（由"领6分当天播种 `last_login_reward_date=当天`"实现，无需单独判断注册日） |
| 总计 | **20积分**（6 + 14） |

> 修正说明（v1.1）：v1.0 中"第1-6天每天2分、第7天4分"=16分，与"14分/总额20分"矛盾。为对齐总额20（与功能名一致），改为每天2分扁平发放，去掉第7天4分。

## 三、数据库变更

文件：`db/V2.4_20260724_login_streak.sql`

```sql
-- 1) 新增3个字段
ALTER TABLE `users`
  ADD COLUMN `login_streak` INT NOT NULL DEFAULT 0
    COMMENT '连续登录天数（0=尚未开始签到）' AFTER `new_user_reward_claimed`,
  ADD COLUMN `last_login_reward_date` DATE NULL DEFAULT NULL
    COMMENT '最后领取登录奖励日期（领6分当天即播种为当天，兼做每日幂等键）' AFTER `login_streak`,
  ADD COLUMN `login_reward_status` TINYINT(1) NOT NULL DEFAULT 0
    COMMENT '签到状态：0-进行中/未开始，1-已完成(满7天)，2-已断签结束' AFTER `last_login_reward_date`;

-- 2) 存量用户全部排除（强制执行）
--    功能全新，无任何存量处于"签到进行中"。默认值为0(进行中)，
--    若不迁移会导致存量用户下次登录被误发2分。
UPDATE `users` SET `login_reward_status` = 2 WHERE `login_reward_status` = 0;

-- 回滚：
-- ALTER TABLE `users`
--   DROP COLUMN `login_reward_status`,
--   DROP COLUMN `last_login_reward_date`,
--   DROP COLUMN `login_streak`;
```

**修正说明（v1.1）：**
- v1.0 用 `created_at` 字段，但 `users` 表注册时间字段实际为 `reg_time`，且无需按日期筛存量--功能全新，所有存量都应排除，故改为 `UPDATE ... WHERE login_reward_status=0`（一句搞定，不依赖任何时间字段，不会误伤边界新用户）。
- v1.0 的 `idx_login_reward_date` 索引删除：签到判定热路径为 `WHERE user_id=?`（主键已索引），`last_login_reward_date` 无范围/批量查询需求，加索引只增加登录写开销。

## 四、登录奖励判定逻辑

### 前置：6分发放时播种

`active.php`（邮箱激活）和 `login.php`（登录补发）发放6分时，**同时**写入：

```
last_login_reward_date = CURDATE()   -- 当天，防止注册/激活当天重复发
login_streak = 0                       -- 尚未开始签到
login_reward_status = 0                -- 进行中
new_user_reward_claimed = 1            -- 6分已发标记
```

> 播种 `last_login_reward_date=当天` 后，注册/激活当天再次登录会被 step2（今日已领）跳过，天然满足"注册当天不额外发"，**无需 step3 的 `registration_date == CURDATE()` 判断**（v1.0 该判断用 `reg_time`，对邮件确认跨天激活场景不准）。

### 签到逻辑 `grant_login_streak_reward($user_id)`（`include/login_reward.php`）

```
1. login_reward_status != 0        -> 跳过（已完成/断签）
2. last_login_reward_date = 今天     -> 跳过（今日已领）
3. last_login_reward_date = 昨天     -> streak += 1（连续；首次签到即 streak 0 -> 1）
4. 否则（含播种后隔天/多天首次登录）   -> login_reward_status = 2（断签结束），不发，返回
5. 发 2 积分
6. streak == 7                       -> login_reward_status = 1（完成）
7. 更新 login_streak / last_login_reward_date = 今天 / login_reward_status
```

> 修正说明（v1.2）：
> - step3 改为**严格起始**：只有播种（领6分）次日登录才开始签到（streak 0 -> 1）；
>   之前"login_streak == 0 任意一天均可开始（宽松起始）"导致领6后隔天登录仍发2分（测试发现不符合"连续登录才奖励"设计），删除该分支。
> - step3/4 合并原 step3~5：`last=昨天` 即连续（无论 streak 是否为 0），否则一律断签，代码更短且规则唯一。
>
> 修正说明（v1.1）：
> - 去掉 v1.0 step3（注册日判断）和 step5（NULL 首次判断），改由"播种 + streak==0 首次分支"统一处理，逻辑更短且规避邮件确认跨天激活边界。
> - 去掉 v1.0 step7 的"streak==7 发4分"，每天统一发2分。
> - v1.0 step6 的"streak>0"限定去掉：任何非连续（含首次跳过）均判断签。

### 并发与幂等

step1~6 为业务计算，step7 用**条件 UPDATE** 抢"今日名额"，天然防并发双发，无需显式行锁：

```php
$affected = pdo_query(
  "UPDATE users SET login_streak=?, last_login_reward_date=CURDATE(), login_reward_status=?
   WHERE user_id=? AND login_reward_status=0 AND last_login_reward_date <> CURDATE()",
  $new_streak, $new_status, $user_id);
if ($affected > 0) {
    point_apply_change($user_id, 2, POINT_LOG_TYPE_SYSTEM, null, '连续登录奖励');
}
```

签到逻辑包裹在 `try/catch` + 事务内，**任何异常只记日志，不阻断登录**（满足验收7）。

## 八、老用户兼容

- `new_user_reward_claimed` 语义：**6分是否已发**（与签到状态解耦）。
- `login_reward_status` 语义：**签到状态**（0/1/2）。两者职责不同，均保留。
- 存量用户：V2.4 迁移将 `login_reward_status` 置2（排除签到）；V2.2 迁移已将存量 `new_user_reward_claimed` 置1（排除6分补发）。双重排除，确保存量完全不参与。
- 新用户：注册/激活发6分后置 `new_user_reward_claimed=1`，并播种 `login_reward_status=0` 进入签到流程。

## 九、验收标准

1. 新用户注册/激活得6积分
2. 连续登录7天：第1~7天每天2积分（共14），第7天标记完成
3. 断签后 `login_reward_status=2`，不再发放
4. 注册/激活当天登录不额外发
5. 同一天多次登录不重复发（条件 UPDATE 幂等）
6. 存量用户不参与（迁移后 `login_reward_status=2`）
7. 登录奖励失败不影响正常登录（try/catch 兜底）
8. 并发登录同一天只发一次（条件 UPDATE 受影响行数=1）
9. （第二阶段）同设备多账号超限可记录风控日志并打断
