# 需求文档：竞赛真题模块（含选择题支持）

> 版本：v2.0
> 日期：2025-04-17
> 项目：HustOJ 题库增强

---

## 1. 产品目标

管理员能够在管理端创建多套竞赛真题试卷，每套试卷可包含单选题、多选题、编程题。普通用户能够做真题、查看每题得分和试卷总分。

**核心原则**：尽量复用现有功能和代码逻辑。

---

## 2. 现有系统复用分析

| 现有功能 | 复用方式 |
|---------|---------|
| contest 表（比赛） | 直接作为「试卷」，不改表结构 |
| contest_problem 表 | 关联试卷和题目，不改表结构 |
| problem 表（题库） | 新增字段区分题型，不改现有字段语义 |
| solution 表（提交记录） | 选择题提交复用此表，code 存答案，result 存判题结果 |
| 管理端 admin/ | 复用现有 UI 风格和权限体系 |
| 用户端做题页面 | 复用 contest.php 做题流程，按题型渲染不同界面 |

## 3. 数据库改动

### 3.1 problem 表新增字段

```sql
ALTER TABLE problem ADD COLUMN problem_type ENUM("programming","choice_single","choice_multi","judge") DEFAULT "programming" COMMENT "题型";
ALTER TABLE problem ADD COLUMN options JSON DEFAULT NULL COMMENT "选择题选项JSON";
ALTER TABLE problem ADD COLUMN answer VARCHAR(500) DEFAULT NULL COMMENT "正确答案";
ALTER TABLE problem ADD COLUMN analysis TEXT DEFAULT NULL COMMENT "答案解析";
ALTER TABLE problem ADD COLUMN score INT DEFAULT 0 COMMENT "每题分值，0表示按默认";
```

### 3.2 contest_problem 表新增字段

```sql
ALTER TABLE contest_problem ADD COLUMN score INT DEFAULT 0 COMMENT "该题在此试卷中的分值";
```

> 不新建任何表，仅扩展现有表。

## 4. 字段使用规范

### 4.1 选择题 vs 编程题的字段映射

| 字段 | 编程题（现有） | 选择题（新增） |
|------|--------------|--------------|
| title | 题目标题 | 题干/简短描述 |
| description | 题目详细描述 | 完整题目内容（支持HTML） |
| options | NULL | JSON选项数组 |
| answer | NULL | 正确答案 |
| analysis | NULL | 答案解析 |
| score | 0 | 每题分值 |
| time_limit | 秒数 | 0（不限制） |
| memory_limit | KB | 0（不限制） |
| input/output/sample_* | 测试数据 | 全部留空 |

### 4.2 options JSON 格式

```json
[
    {"label": "A", "content": "printf语句中格式化字符串可以包含中文"},
    {"label": "B", "content": "C++程序只能用英文编写"},
    {"label": "C", "content": "双引号可以替换为两个单引号"},
    {"label": "D", "content": "每个双引号都可以替换为三个双引号"}
]
```

### 4.3 solution 表复用方式

| 字段 | 编程题提交 | 选择题提交 |
|------|-----------|-----------|
| problem_id | 题目ID | 题目ID |
| user_id | 用户ID | 用户ID |
| contest_id | 比赛ID | 试卷ID |
| code | 源代码 | 用户答案（如 "A"、"ACD"） |
| language | C/C++/Python/... | 固定值 99（选择题标记） |
| result | 0=待判 4=AC 6=WA | 4=正确 6=错误 |
| time | 运行时间 | 0 |
| memory | 内存使用 | 0 |
| valid | 1=有效 | 1=有效 |

选择题不经过评测机判题，PHP 直接比对 answer 字段后写入 result。

## 5. 管理端功能

### 5.1 试卷管理 — 不改

现有 contest_add / contest_edit / contest_list 保持不变。
管理员创建试卷 = 创建 contest，添加题目 = 添加 contest_problem。

### 5.2 选择题题目管理

#### 5.2.1 problem_list.php 改造
- 列表新增「题型」列
- 筛选新增「题型」下拉

#### 5.2.2 problem_add_page.php 改造
- 页面顶部新增「题型选择」：
  - 编程题（默认，表单不变）
  - 单选题 / 多选题 / 判断题

- 同 problem_add_page.php，按题型加载对应表单

#### 5.2.4 problem_add.php 改造
- 接收并保存 options / answer / analysis / score 字段

## 6. 用户端功能

### 6.1 做题页面

用户进入 contest.php?cid=xxx 后：

**选择题**：
- 显示题干 + 选项（单选用radio，多选用checkbox）
- 底部「提交答案」按钮
- 提交后立即判题，显示对错 + 正确答案 + 解析

**编程题**：
- 保持现有代码编辑器 + 提交 + 判题流程不变

**页面导航**：
- 顶部显示试卷题目列表（1. 单选题 2. 编程题 ...）
- 点击跳转
- 每题状态（未答/已答/正确/错误）

### 6.2 试卷成绩页

- 试卷总分 = 各题得分之和
- 每题详情：题型、用户答案、正确答案、得分
- 可选：班级排名（复用排行榜）

## 7. 判题逻辑

```
用户提交选择题答案
    ↓
PHP 接收 answer 参数（如 "A" 或 "ACD"）
    ↓
从 problem 表读取 answer 字段（正确答案）
    ↓
比对：
  单选题/判断题：精确匹配（忽略大小写，trim空格）
  多选题：排序无关匹配（"ACD" == "CDA"）
    ↓
写入 solution 表：
  result = 4 (AC) 或 6 (WA)
  code = 用户答案
  language = 99
  time = 0, memory = 0
    ↓
更新 contest_problem.c_submit / c_accepted
```

不做部分得分：选择题要么全对要么0分。
