# 题目导入模板格式规范

> 规范 GESP 竞赛真题导入模板（选择题 CSV / 编程题 XML）的书写格式，便于后续新增真题或修订模板时对照检查。

---

## 一、文件命名与组织

```
docs/竞赛真题/
├── 选择题批量导入模板.csv            # 选择题 CSV 模板（含示例）
├── 编程题批量导入模板(FPS格式).xml    # 编程题 FPS XML 模板（含示例）
├── 编程题导入说明.md                  # 编程题导入字段说明（已有）
├── 题目导入模板格式规范.md            # ← 本文档
└── GESP_{年月}_{语言}/               # 某次真题目录
    ├── GESP_{年月}_{语言}_L{等级}_选择题.csv
    ├── GESP_{年月}_{语言}_L{等级}_编程题.xml
    └── ... L1 ~ L8 同理
```

命名约定：`GESP_{年月}_{语言}_L{等级}_选择题.csv` / `GESP_{年月}_{语言}_L{等级}_编程题.xml`。

## 二、选择题 CSV 格式规范

### 2.1 字段顺序（共 13 列，顺序固定）

```
题目类型,题目内容,选项A,选项B,选项C,选项D,选项E,正确答案,分值,难度,竞赛来源,标签/分类,解析
```

| 字段 | 说明 |
|------|------|
| 题目类型 | `单选` / `多选` / `判断` |
| 题目内容 | 题干，含代码时需转义（见 2.3） |
| 选项A~E | 不足 5 个选项的留空（判断题只有 A/B） |
| 正确答案 | 单选填 `A`~`E`；多选填组合如 `BC`；判断填 `A`(正确)/`B`(错误) |
| 分值 | 数字，如 `2` |
| 难度 | `简单` / `中等` / `困难` |
| 竞赛来源 | 如 `GESP-2026.03` |
| 标签/分类 | 如 `C++ 3级 真题 单选题` |
| 解析 | 官方答案或推断依据 |

### 2.2 多行单元格写法

题目内容或选项中包含多行代码时，**整个字段必须用双引号包裹**，字段内的双引号需用 `""` 转义：

```csv
单选,"关于以下程序段,说法正确的是（ ）。
int x=10;
cout&lt;&lt;(x++) + (++x)&lt;&lt;endl;",选项A,选项B,选项C,选项D,,A,2,...
```

### 2.3 特殊符号转义（重点）

导入系统会把 CSV 单元格内容当作 HTML 渲染，**未转义的 `<` `>` 会被识别为 HTML 标签**，导致题面/代码显示错乱甚至内容丢失。因此单元格内所有 `<` `>` 都必须转义：

| 原符号 | 转义为 | 常见场景 |
|--------|--------|----------|
| `<` | `&lt;` | `i &lt; n`、`vector&lt;int&gt;`、`cout &lt;&lt; x` |
| `>` | `&gt;` | `j &gt; 0`、`a[j] &gt;= key`、`node-&gt;val` |
| `<<` | `&lt;&lt;` | `cout &lt;&lt;` |
| `->` | `-&gt;` | `s-&gt;next`、`cur-&gt;val` |
| `<=` | `&lt;=` | `i &lt;= n` |
| `>=` | `&gt;=` | `a[i] &gt;= x` |

> 注意：已经写成 `&lt;` `&gt;` 的不要重复转义（避免出现 `&amp;lt;`）。

### 2.4 代码缩进规范

- 统一使用 **4 空格缩进**（同一文件内保持一致）
- 函数体、循环体、条件分支体、结构体成员均需缩进
- 嵌套层级每层 +4 空格
- 运算符两侧保留空格：`i = 1` 而非 `i=1`；`for (int i = 0;` 而非 `for ( int i=0;`

### 2.5 常见错误（禁止）

1. **选项内残留行号**：从 PDF 复制代码时带入了 `1 ` `2 ` `3 ` 等行号前缀，必须删除。
2. **题目内容缺失数值**：如 `三进制数 转换成十进制` 漏了具体数字。
3. **缩进丢失**：函数体/循环体顶格写，无缩进。
4. **符号未转义**：`<` `>` 直接裸写。

## 三、编程题 XML (FPS) 格式规范

字段含义、测试数据写法等见同目录 [`编程题导入说明.md`](./编程题导入说明.md)，此处仅补充格式要点。

### 3.1 标签缩进

- XML 标签统一 **4 空格缩进**，层级清晰
- `<item>` 下的子元素缩进一致

### 3.2 标签内容转义

`<description>` `<input>` `<output>` `<hint>` 等**标签内的文本**中，`<` `>` 同样需转义为 `&lt;` `&gt;`（XML 本身的标签尖括号不动）。常见于数据范围说明：

```xml
<hint>保证 1 &lt;= N &lt;= 10000。</hint>
```

> 若内容含较多特殊字符，可改用 `<![CDATA[ ... ]]>` 包裹（参考模板文件），CDATA 内部无需转义。

### 3.3 样例与测试数据一致性

- `<sample_input>` / `<sample_output>` 必须与 `<hint>` 中描述的逻辑自洽（如偏移量、样例解释）
- `<test_input>` / `<test_output>` 的 `name` 需一一配对，多测试点写成多个同名配对节点（详见导入说明）
- 多组输入题目才把多组数据写在同一节点内，并在题面说明

## 四、导入前检查清单

| # | 检查项 | 自检方法 |
|---|--------|----------|
| 1 | 题干/选项内容完整，无遗漏数值 | 人工通读 |
| 2 | 选项内无残留行号（`1 ` `2 `） | 搜索 `\n\d ` 或人工查看多行选项 |
| 3 | 代码缩进统一为 4 空格 | 人工查看多行代码块 |
| 4 | `<` `>` 已转义为 `&lt;` `&gt;` | 见下方命令 |
| 5 | 无重复转义（`&amp;lt;`） | 搜索 `&amp;lt;` / `&amp;gt;` |
| 6 | CSV 多行字段双引号包裹正确 | 用 Excel/Numbers 打开验证列对齐 |
| 7 | XML 样例与 hint 逻辑自洽 | 验算样例 |
| 8 | test_input / test_output 配对一致 | 检查 name 属性 |

### 快速检查命令

```bash
# 查找 CSV 单元格内裸写的 < 或 >（排除已转义的 &lt; &gt;）
grep -nE '[^&]<|[^&]>' docs/竞赛真题/GESP_*/*.csv

# 查找重复转义
grep -n '&amp;lt;\|&amp;gt;' docs/竞赛真题/GESP_*/*.csv

# 查找选项行首残留的行号（多行字段内以 数字+空格 开头的代码行）
grep -nE '^[0-9]+ ' docs/竞赛真题/GESP_*/*.csv
```

## 五、录入流程与维护建议

### 5.1 从真题 PDF 录入的三步法

1. **删行号**：清理代码块中被复制的行号前缀（`1 ` `2 ` `3 `）。
2. **补缩进**：按 4 空格规范补齐函数体/循环体/结构体缩进，运算符两侧加空格。
3. **转义符号**：把 `<` `>` 转义为 `&lt;` `&gt;`（含 `<<` `->` `<=` `>=`）。
4. **补选项**：单选/多选题必须填写选项 A~D（至少 A、B），导入系统会校验，选项为空会报错"至少需要填写选项A和B"。

### 5.2 维护建议

- **新增真题**：复制现有同等级文件作为底稿，避免格式从零开始。
- **提交前**：跑一遍第四节检查清单的 grep 命令，确认无裸写 `<` `>`、无重复转义。
- **样例验算**：编程题必须手工验算 sample_input -> sample_output，并与 hint 解释一致。
- **内容缺失**：若发现题面数值/符号缺失（如某 input 缺数量词），记录并提示出题方补充，不擅自编造。
- **选项完整性**：单选/多选题选项易遗漏（尤其是时间复杂度/组合数学题），导入前用下方命令扫描。
- **编程题样本数据**：`<sample_input>`/`<test_input>` 行数须与题目输入格式严格对应，勿带入 PDF 中的题号/分值行。
- **时间复杂度文本格式**：用 `O(n^2)` 形式（`^` 表示上标），`log3` 表示以 2 为底 3 的对数。

### 5.3 检查选项完整性的命令

```bash
# 查找单选/多选题选项A-D全空的记录（答案前有5个连续逗号）
grep -nE ',,,,,[^,]+,' docs/竞赛真题/GESP_*/*选择题.csv
```

> 判断题选项固定为 A="正确"/B="错误"，不会为空；仅单选/多选题可能漏填，导入系统强制要求至少填写 A 和 B。
